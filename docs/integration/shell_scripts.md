# `.sh`文件是做什么的？

它们是Linux服务器上的批处理脚本：把一串Python命令和参数写在一个文件中，负责依次训练、保存日志、跳过已完成任务，部分脚本还会并行调度。它们不是权重，也不是模型算法本身。

| 文件 | 实际用途 | 现在如何处理 |
|---|---|---|
| `run_four_holdout.sh` | 对A/B/C/D四种混合／蒸馏组合，按42、2024、3407运行；混合比例0.75 | 历史消融启动记录，保留 |
| `run_holdout_lane.sh` | 将上述四组实验按种子分成两路；含旧服务器路径和旧进程号 | 历史调度脚本，不能原样当作新服务器通用启动器 |
| `run_m0_05625.sh` | 比例0.5625的混合训练、不使用蒸馏，随后测试，作为蒸馏消融 | 与Xu研究相关，保留 |
| `run_normal_only.sh` | 仅正常组：N0无蒸馏、N1有蒸馏；两路各跑三个种子 | 基础模型及其蒸馏消融，保留 |
| `run_ready_tests.sh` | 检查已有模型，对训练完成且尚未完成测试的模型进行测试 | 不负责重新训练，保留 |

这些脚本是Xu研究的一部分，不是与项目无关的旧小车文件。此次没有执行它们，也没有启动新的实际训练。

## 平时需要打开它们吗？

不需要。查看整合项目说明，使用 `python project.py list` 和各方法的帮助即可。GUI通过 `python project.py run gui` 打开。

## 什么时候使用？

要在Linux服务器批量重现实验时，检查脚本中的数据路径、模型目录、种子、混合比例、训练轮数和旧进程号，再选择需要的脚本。脚本可能启动多项长时间训练，不要为了查看而执行。

Linux通常用 `bash 文件名.sh` 执行；Windows PowerShell不能直接把它当作Python运行。单个模型不必用批处理脚本，可使用统一Python入口。
